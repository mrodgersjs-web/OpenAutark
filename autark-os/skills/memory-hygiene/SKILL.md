# Memory hygiene

I read this whenever I write to memory: a company note, a person's reference, a lesson, a state
file. Memory is an asset only while it is true.

## Rules

1. **Every durable claim carries an absolute date.** "Revenue is 40K" rots; "Revenue 40K
   (2026-11-23, from the invoice ledger)" does not.
2. **One source per claim.** A path, a URL with its read date, or "the person said so on <date>".
3. **Reconcile on write, not on read.** If new evidence contradicts an old line, fix the old line
   in the same pass and note what changed. Never leave two truths side by side.
4. **A page is an index, not a warehouse.** Detail goes to the page it belongs to; the summary
   keeps the pointer. Appending forever makes memory unreadable and slow.
5. **Corrections win.** The person's newest words beat any earlier note, including my own.
6. **No secrets in memory.** Handles only (`secret://…`), never values.
7. **Write a receipt.** After writing, read the file back. "Saved" is a claim, not a hope.

## Steps

1. Decide the destination: company memory, a branch (area), an agent's own memory, or a chat.
2. Write the smallest true statement, with its date and source.
3. Search for a contradicting line first. If one exists, this is an edit, not an addition.
4. Re-read after writing; if the file did not change, the write failed - say so.

## Guardrails

- Never store a guess as a fact to be helpful later.
- Never copy a whole document into memory; link it.
